# 精确户型与复式住宅建模研究

调研日期：2026-09-05。本文件保留实施前的研究与备选设计；「现有代码」指当时的旧矩形实现，示意类型不等同当前 schema。已交付能力以 [精确户型模块](precision-floorplan/README.md) 为准。范围：住宅 DIY 空间还原、尺寸编辑与三维预览。本文件是本项目的设计建议，不代表已实现能力，也不声称满足施工图、结构设计、消防或建筑面积计算规范。

## 结论

要可靠还原带矛盾尺寸、复式层与挑空的多张户型图，先建立“来源图与尺寸证据 → 可校准的结构模型 → 房间与楼板 → 家具”的流程。继续把一切压进矩形房间及全局墙高，会让识别结果在进入编辑器前就丢失信息。

建议把**墙体、楼板及其开口作为可编辑的结构事实，房间作为空间语义，楼层作为标高容器**。门窗引用真实墙体，挑空引用楼板洞口。采用能直接生成网格的二维线段、多边形和高度参数，不引入完整 BIM 数据库或通用 CAD 求解器。

多张来源图应分别保留来源、楼层、版本和尺度。原图读数及冲突清单须在图像分析阶段单独记录，不能把下文示意数值当作住宅实测数据。

## 最小可实施模型

### 1. 坐标、单位与楼层

继续使用平面 x/z、竖向 y，统一内部长度单位为米。默认显示毫米或米，并允许切换；输入 3.437m 必须能原值往返，不能在提交时固定舍入到 5cm。网格吸附只影响拖动操作；几何比较 epsilon 与真实尺寸容差分别配置，避免把计算误差当作吸附依据。

`Level` 至少包含 `id/name/elevation/slabThickness/defaultWallHeight`。第一版将 elevation 明确定义为该层地面的简化完成面标高；楼板体位于 `elevation - slabThickness` 到 `elevation`。相邻完成面标高差用于显示层间高度，墙高可以覆盖默认值。首版不增加未知饰面层厚度，界面也不把这种简化净空称作 IFC 的精确数量。

例：上层标高 3.20m、上层板厚 0.15m、下层标高 0，则上层板底相对下层地面为 3.05m。若后来加入梁或吊顶，还要分别减少实际净空；不能把 3.20m 直接显示为房间净高。此例仅说明计算口径。

同一平面坐标在不同 level 可以出现房间，冲突检查按楼层与垂直范围进行。楼层选择影响编辑对象与显示，不能通过改变 x/z 把二层搬到一层旁边冒充多层。

### 2. 墙基线是结构坐标的唯一来源

建议第一版存储以下概念，字段名可在实现时调整：

```ts
type Point2 = [x: number, z: number]
type Polygon2 = { outer: Point2[]; holes: Point2[][] }

type Wall = {
  id: string
  levelId: string
  startNodeId: string
  endNodeId: string
  thickness: number
  alignment: 'center' | 'left' | 'right'
  baseOffset: number
  height: number
}

type WallOpening = {
  id: string
  wallId: string
  kind: 'door' | 'window' | 'open'
  offset: number // 从有向墙基线起点到洞口中心的实际米数
  width: number
  bottom: number // 相对墙基部
  height: number
}

type Slab = {
  id: string
  levelId: string
  shape: Polygon2
}
```

同层端点作为可复用节点保存位置，墙引用节点 ID，保证共端点编辑一次更新。已有长墙遇到 T 接头时先切段并迁移开口所属段；仍保持稳定墙 ID，不用坐标字符串充当业务 ID。T/L 接头的实体拼接由几何函数处理，房间标签和家具生成不参与决定墙是否存在。

基线方向决定左右，反转方向要同步调整 alignment 及 `offset' = wallLength - offset`，可见实体和洞口世界坐标应不变。编辑墙厚时沿选择的基线对齐方式增厚；若用户选择“保持室内净尺寸”，将其转换成锁住相应内皮位置的明确操作，而非悄悄移动另一侧。

第一版只支持直墙，直角吸附是默认交互，基础线段结构无需只允许 n/s/e/w。弧墙、分层墙材质、任意曲面和复杂实体布尔不进入首轮范围。

### 3. 房间轮廓不再反向决定每面墙

墙的内皮和虚拟分区线围出空间多边形。保存房间的稳定 ID、名称/用途、levelId、坐标框架、种子和一个内部定位点；边界通过墙图计算并按定位点关联回房间。开放式客餐厅用虚拟分区线切分使用空间，虚拟线不生成墙。

核心约束是**不保留两套可以独立修改的结构坐标**。用户拖房间边，应翻译为移动关联墙或虚拟分区线的单次事务，然后重新求房间轮廓；不能一边维护 RoomDef.rect，另一边独立维护 walls。面积等读数从净空间多边形计算，房间 AABB 只是派生值。

凹多边形、洞口和闭合检查属于必要能力；第一版不必提供任意拓扑的自动纠错。自交、未闭合、零长度边直接指出位置，保留编辑草稿，不把异常图形自动改成矩形。房间分裂/合并时清楚分配标签和家具归属；不得静默丢掉已有家具。

原有矩形生成器可暂时只对确实为矩形的空间提供完整自动布局。非矩形空间先支持手工摆放，或在内部矩形候选区域生成后做真实多边形包含检查；不能把外接矩形生成结果不经检查直接放入 L 形房间。临时的内部切分不得生成假墙或多个用户房间。

### 4. 门窗、挑空、护栏与楼梯各自有宿主

- 门窗仅引用 wallId，沿基线移动；洞高和底标高参与立面切洞。两侧房间由空间关系推导，避免 a/b 和实际墙位置两套信息互相冲突。移动墙会带动洞口，删除墙明确处理所带门窗。
- 室内打通是墙洞；全墙拆除是删除墙并处理空间合并。阳台护栏是有高度、路径的围护对象，不复用“通高开洞产生半墙”的渲染特例。
- 挑空/楼梯洞是上层楼板的真实孔洞。内部孔洞进入 `shape.holes`；延伸到板外缘的缺口直接修改 outer，不能构成贴边或越界的非法 hole。
- 凸出的局部二层地面与下层房间面积不必相同；三维天花由上层板底或独立天花区域给出，不在挑空下方自动补完整天花。
- 楼梯最少保存 fromLevelId/toLevelId、平面占地或梯段路径、宽度、平台及踏步数；总升高来自两层标高差，并关联上层板洞。先实现直梯与带平台折返梯，能检查踏步顶部是否接上层、楼板洞是否覆盖行走路径。上述检查是几何一致性，不是法定踏步或净高合规判断。
- 跨层窗要显式关联能覆盖其高度的墙；可用一面跨层高墙作宿主并在不同楼层显示切片，避免“放一个窗后自动切所有看似相邻的墙”。若实现选择分层墙，则需要一个明确的跨层开洞分组事务，不能静默复制互不关联的窗。

## 多图输入与冲突尺寸的处理流程

1. **逐图归档。** 给每张图片稳定 sourceId，记录像素尺寸、用户说明、所属楼层、图纸类型与修订关系。照片/透视效果图只能提供形态证据，不能与正投影平面图共用同一尺度。总平图与局部放大图也应分别标定。
2. **逐条记录读数。** 保存标注原文、米制值、图上的两端点或范围、目标构件、尺寸口径（内皮/外皮/轴线/未知），以及“用户确认/图纸读数/图像估测”。读不清时保留候选或未知，不替换成默认门宽等数值后丢失来源。
3. **先校准再描图。** 在可靠标注上点击两个端点，按 `metersPerPixel = knownLength / pixelDistance` 建立比例，再设方向与原点。另一条尽可能正交、跨度较大的尺寸用作独立复核。多张图各自有变换，通过明确公共点对齐到楼层坐标。
4. **识别矛盾，不自动平均。** 先检查单位、楼层、版本、内外皮/轴线口径，再比较同一测量对象。若分段之和与总长不符，列出每个来源和残差；只有用户确认的尺寸成为驱动值，其余保留为参考读数。不要默认最新图片必然最准确，也不要让模型置信分数替用户裁定。
5. **谨慎处理畸变。** 单一尺度解释不了多条确认尺寸时，提示可能有截图拉伸、透视或不同测量口径。只有有足够控制点和明确变换含义时才启用二维仿射/透视校正；不能为了消除矛盾而默认分别缩放 x/z。
6. **先输出结构草稿。** 先核对各楼层轮廓、墙厚、关键尺寸、楼板缺口和楼梯连接，再生成家具。缺失的标高/板厚标为假定值，并在属性中可追溯；不会因为 3D 看着合理就变成“已测量”。
7. **确认过程可撤销、可保存。** 标定、选择冲突读数、移动共享墙和应用 AI 建议均为一次明确编辑；工程包保存来源图与所采用尺寸，刷新或换机器仍能解释模型为何是这个大小。只调整底图校准不得悄悄缩放已有结构；确需整层缩放应另作显式操作。

最少需要一张 `DimensionEvidence` 表：`id/sourceId/target/valueM/referenceKind/status`，附原图定位。需要比较残差时按当前几何即时计算，不持久化同一残差的多个副本。无需第一版就实现通用约束求解；先做好端点坐标、墙长、平行/直角吸附与选定基准边固定的直接编辑。

## 实施次序与兼容边界

| 阶段 | 可独立交付的结果 | 完成标准 |
| --- | --- | --- |
| A：证据与精确输入 | 多来源图、尺度/原点标定、尺寸读数与冲突列表；模型可保留毫米级输入。 | 3.437m 输入/保存/打开不变；矛盾尺寸不被静默合并；旧自动修复不作用于确认尺寸。 |
| B：墙与空间 | 稳定墙/节点 ID、可变墙厚、墙宿主门窗、凹多边形房间、尺寸标注。 | 改厚度口径明确；改房型不改墙；门窗与墙同步；L 形缺口没有假墙、假地板或落在室外的家具。 |
| C：复式结构 | 楼层标高、楼板轮廓与洞口、简单楼梯、分层显示及下层参照。 | 上下层可重叠；挑空同时在俯视和仰视中可见；楼梯起终点接对标高；单层视图不改写真实坐标。 |
| D：识别与回归 | AI 先提议证据与几何，用户选择后进入统一结构动作；完整工程往返。 | 用矛盾尺寸、窄空间、凹形、两层挑空、共享墙缩放、跨层窗样例覆盖操作链。 |

这些是依赖顺序，不意味着每阶段都建立一套独立状态系统。先加纯类型/几何函数与 fixtures，再连 store/history、保存格式和 UI；集中转换旧数据一次，新旧工具不能同时成为同一方案的结构来源。

旧 HomeDef 迁移到默认 level；旧墙几何可作为迁移输入，保留尽可能相同的可见位置、0.12m 厚度和家具世界坐标。由于旧数据没有净尺寸/轴线的统一测量口径，不能声称迁移会恢复真实尺寸；标记为“旧方案近似几何”。由旧矩形推导的房间坐标框架保持稳定，切换新计算方式时不把家具重新归中。

`.home3d` 工程包需要新版本并保留旧版读取器；source images/evidence、levels/walls/slabs/openings/stairs 必须在同一次导入校验和历史快照中更新。轻量 v1 不能完整表达复式与凹形：继续允许读取，导出时必须明确不支持或显式选择降级，不无声压平楼层。跨仓库同步需逐项移植、独立验证，不包含个人原图或私有路径。

## 必须锁住的回归

- 尺寸：内皮与轴线标注给出不同且可解释的值；调整墙厚后符合所选固定基准；正反墙方向不改变洞口世界位置。
- 拓扑：共享墙只存在一次；移动节点保持连接；墙段拆分/合并维护门窗宿主；未闭合草稿不会覆盖有效方案。
- 多边形：L 形面积按实际轮廓计算；凹角/洞口不会产生跨外部三角面；门区和家具可用范围以净空间判断。
- 多层：平面重叠不误判冲突；板底标高正确；上层孔洞不会删除下层地面；楼梯及挑空边界在不同视角一致。
- 证据：同一对象多个读数并存；冲突保留出处和选择记录；应用/撤销/打开工程不会丢掉未采用读数。
- 存储：旧 v1 工程可读；新版复式工程往返后几何、宿主、图纸和家具 ID 引用一致；不经过旧 importPlan 的夹取修复。

现阶段最值得避免的额外复杂度：完整 IFC 导入导出、施工规范自动审查、通用三维 CSG、弧墙/NURBS、全局多变量约束求解，以及为未知数据自动猜出“标准”墙厚/层高。先让用户明确输入、确认和追溯真实尺寸，再扩展自动化。
