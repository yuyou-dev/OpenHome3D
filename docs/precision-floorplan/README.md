# 精确户型里程碑

本模块已移植到 OpenHome3D，与原有模板编辑兼容。研究依据见 [实施前设计研究](../precision-floorplan-research.md)，公开验证说明见 [验证范围](results.md)。此模块面向住宅布局、家具 DIY 与三维核对；栅格图识别不能替代实测 CAD 或施工图审查。

## 使用与核对

1. `npm run dev`，打开终端给出的随机端口。整宅 → 导入户型图。识别使用本机已登录的 Codex CLI，显式模型 `gpt-6-astra`，识别推理强度 `medium`（重绘编排仍为 `high`）。本地姊妹项目的私有样本测试中，high 曾触及 600 秒上限，因此识别与重绘采用独立推理档位；该记录不代表 OpenHome3D 已重新进行真实九图测试。复杂图可能需数分钟，服务端上限 600 秒，识别期间显示置顶模态进度，可点「放弃识别」或 Esc 取消；排队放弃不会中止其他任务。
2. 识别成功自动进入原图/解析叠加核对，确认后点「导入」一次应用结构与原图；「放弃导入」或 Esc 返回原方案。蓝色表示空间轮廓与墙，粉色表示门洞，黄色表示窗，虚线表示挑空。叠加数据与三维场景来自同一个米制结构对象，不使用另画的示意图冒充结果。
3. 导入后，专业结构面板提供空间/楼层选择、正北朝上的顶视、原图叠加、尺寸冲突提示、统一比例校准、墙厚/墙高、门窗位置/宽高/窗台及铰链/开向编辑。非法洞口会被拒绝；仅导入时允许不超过 2 像素的端点裁切并明确记录，不会默默移动到墙中间。
4. 家具按识别类别、名称、尺寸和朝向匹配现有资产；有匹配的家具优先在原位置落位并锁定。床类不会因资产名称含 bed 而误选床头柜；真床仅因贴墙尺寸差或门前净空无法原位落下时，允许半径 20cm 内的最近合法平移并记录厘米数，保留原识别中心、尺寸和方向。整间没有可用匹配时才使用现有生成器提供候选，最后检查真实轮廓、墙、门前净空、楼梯和挑空。无法放置的家具会报告，不缩小房间或替换成不相干物件。
5. 保存 `.home3d` 或「仅布局」JSON 都保留专业结构、空间 ID 和楼层。`.home3d` 额外携带原图及使用的上传模型/参考照片。撤销重做包含结构参数与导入操作；历史仍为 50 步会话历史。

专业方案不会再调用旧的矩形房间拖拽/缩放、邻接墙推导或 5cm 修复器。旧模板与旧 JSON 仍走原有编辑流程。两种数据路径按 `home.architecture` 区分；不是同时叠加两套墙。

## 几何与解析契约

- `scripts/plan-schema.mjs` 为唯一识别 schema/prompt。wire `version:2` 使用原始完整图片像素：x 向右、y 向下。墙中心线、空间多边形、厚度、沿墙开口和家具足迹先在同一像素坐标系描出；`source.scale` 为米/像素。层标高、墙/洞高、窗台和楼梯升高直接使用米。
- `src/gen/importArchitecture.ts` 统一换算单位与校验，不吸附、不移动房间、不把非矩形变成矩形，也不强制所有房间至少 1.5m。原图映射固定为 `(pixelX * scale, pixelY * scale)`，故导出后仍可叠回原图。导入规范化仅包括：≤2 像素宿主端点裁切、栏杆通行缺口高度截到栏顶、明确飘窗标签改为不可摆家具的 ledge；每项均记录提示；真实测试应另行保留原始模型响应，不覆盖为转换后的结构。统一校准同时缩放家具与梯段平面，保留垂直高度，更新当前尺寸冲突；两种工程格式都不得夹取校准后的家具比例。
- `home.architecture.version:1` 是米制持久化结构。`levels` 保存层名、标高和高度；`spaces` 保存实际多边形及 room/balcony/void/stair/ledge 语义；`walls` 保存独立中心线、厚度、高度与内/外/栏杆分类；`openings` 通过稳定 `wallId` 关联宿主。
- `home.rooms` 是从空间轮廓派生的兼容选择/家具坐标框架，矩形只是 AABB。不得用这些 AABB 生成专业模式的墙、地板、面积或最终家具包含判定。同名次卧保留不同 ID；楼层不同可以重叠投影。
- `architectureGeometry.ts` 负责多边形/挑空差集、地板与墙基覆盖、任意角度墙体足迹、转角衔接、门窗洞实心区域和楼梯实体。3D 由 `ArchitecturalHome` 渲染：真实外轮廓、不补外侧凹口、挑空无楼板，门窗洞与实体共用几何。
- 窗台 ledge 排除普通地板和家具，抬高高度为推定值并记录提示。栏板上的玻璃可以高过栏板，普通墙/门洞高度限制保持严格。顶视按 1.2m 剖切露出门洞，轴测恢复完整墙高。
- 当前交互按楼层单独查看，该层显示基面为 y=0，标高作为明确元数据保留。分别导入的复式上下层图不会在基点不确定时自动拼接。多层数据可通过工程 JSON 保存；尚不承诺多图片自动配准和复式整楼联动编辑。
- 楼梯可保存识别到的多跑中心线路径、宽度、升高与级数，以及平台。stairConnection 明确本层上行/下接/未知；下接梯顶端对齐本层，踏步在楼板下方且占区扣孔，不按楼层编号猜连接。缺失方向/梯段只显示并报告示意，不能凭“上/下”字样虚构未见楼层；层高与每跑升高仍需实测确认。
- 尺寸标注保留驱动依据与冲突状态。采用统一比例后，与标注差异超过 5% 的尺寸记为冲突并显示数值残差；不做非均匀拉伸，也不把建筑面积标题当净地面面积。
- 当前专业参数编辑覆盖统一比例、墙厚/高及已有门窗属性。自由绘制/拖拽多边形顶点、墙节点拓扑编辑、DWG/DXF/IFC 交换、结构承重属性和建筑规范自动审查不在本轮实现范围内。

## 验证与证据

公开回归使用仓库合成样例 `scripts/fixtures/plan-precision.json`，不包含个人住宅图片或人工坐标：

```sh
npm run check
npm run check:ui
npm run smoke:architecture
npm run smoke:precision:ui
npm run smoke:pages
```

`smoke:architecture` 检查结构几何、导入、家具、工程往返与状态；`smoke:precision:ui` 在隔离浏览器中模拟 AI，验证上传 → 置顶识别 → 自动核对 → 放弃或导入 → 参数编辑/拒绝/撤销/重做，并检查桌面、手机和短屏下的图片可见性、焦点与背景隔离。常规门禁不会调用真实 Codex。

需要真实验证时，可使用应用导入自有图片，或明确运行 `npm run smoke:ai:live -- --run` 完成一次合成户型识别和一次效果图生成。后者消耗账号额度，不属于常规 `check/check:ui`。私有九图的原图、人工真值、文件名清单、原始模型响应和测试工程不随本仓库发布；不能把姊妹项目的真实结果当作开源版独立实测。去敏摘要见 [验证范围](results.md)。

新样本验收应先独立记录来源读数与不确定项，再检查确定的外轮廓、内墙、关键开口、公共通路、楼梯/挑空和浏览器错误。不得依据模型输出反写真值或调整阈值。抽样结构通过不能证明每个像素、家具或工程尺寸达到实测 CAD 精度。

## 发布与兼容边界

OpenHome3D 保留自己的浏览器存储键、Pages 子路径、社区入口和 Companion 生命周期。共享结构/状态/渲染/UI 的变更需独立验证开源版；main 推送后的部署结果以 GitHub Actions 为准。GitHub Pages 可打开和编辑已保存的专业方案，但不提供本机 AI 端点；识别需要本机 `npm run dev` 与已登录的 Codex CLI。

原图放大、识别进度和核对界面统一使用 `PlanDialog` 原生顶层模态：阻止背景点击与键盘焦点，标题与底部操作固定，图片等比完整显示；查看已导入原图和手动核对使用「关闭」。详见 [导入交互](import-interaction.md)。
