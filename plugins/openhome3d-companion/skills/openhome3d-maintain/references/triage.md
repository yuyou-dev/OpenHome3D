# Triage rules

- `Q&A`: answer with verified behavior; mark an answer only when it resolves the question.
- `Ideas`: clarify the user outcome before turning it into an implementation issue. Keep promising but uncommitted ideas open for discussion.
- `Show and tell`: acknowledge the contributor and preserve the thread as community material.
- Bug Issue: reproduce, record environment and minimal steps, then decide fix/defer/close.
- PR: verify intent, actual diff, tests, public-code boundaries, and authorship before recommending a merge.
- Duplicate: link the canonical item and preserve useful new evidence before closing.
- Spam or unsafe content: recommend moderation with a concise reason.

Close the loop after action: link the implemented change, thank the contributor, update documentation when the question is likely to recur, and note any sibling-project synchronization still pending.
